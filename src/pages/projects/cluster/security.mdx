# Безопасность и эксплуатация Cluster

- Храните общий секрет вне Git и используйте случайное значение достаточной длины.
- Ограничьте служебные порты Registry и межузловые Gateway firewall правилами.
- Считайте общий секрет аутентификацией узла, а не шифрованием или авторизацией приложений.
- Сверяйте адрес узла с доверенной сетью; не принимайте служебные соединения из произвольных источников.
- Перед обновлением проверяйте совместимость всех узлов и клиентов с выбранным wire protocol.
- Cluster использует PHP `serialize()` для тел сообщений и сессий. `unserialize()` по умолчанию не создаёт переданные классы: массивы и скаляры остаются совместимы, сериализованные пользовательские объекты становятся `__PHP_Incomplete_Class`.
- Для изолированной доверенной сети, где сессии действительно содержат объекты, задайте `localzet\Cluster\Protocols\Cluster::$allowObjectSerialization = true` до запуска всех узлов. Не включайте режим, если хотя бы один peer не полностью доверенный.
- Планируйте поведение при потере Registry, Gateway и Business Worker отдельно; текущие регрессионные тесты не покрывают распределённый failover.

Перед публичной эксплуатацией нужна отдельная оценка сетевой модели, отказоустойчивости, ограничений нагрузки и восстановления состояния.
