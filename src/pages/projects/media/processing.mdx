# Обработка и выдача изображений

Маршрут по умолчанию: `GET /app/media/processing/{image-id}/{filter}/{parameters}`. Каждый фильтр и его параметры занимают по одному segment пути. Можно последовательно применить несколько фильтров; порядок в URL задаёт порядок обработки.

## Фильтры

| Фильтр | Формат | Пример |
| --- | --- | --- |
| `resize` | `width` или `widthxheight` | `/image-id/resize/640` |
| `crop` | `width`, `widthxheight` или `widthxheight&x,y` | `/image-id/crop/320x240&20,10` |
| `pixelize` | `pixels` | `/image-id/pixelize/24` |
| `cover` | 3- или 6-значный hex-цвет без `#` | `/image-id/cover/f2f4f7` |

Пример цепочки:

```text
/app/media/processing/image-id/resize/640/crop/320x240
```

`resize` сохраняет пропорции, если передана только ширина или высота. `crop` без координат масштабирует и кадрирует по центру; координаты задают область в исходном изображении. `cover` формирует фон фиксированной ширины. Все параметры должны соответствовать лимитам `max_image_pixels`.

## Формат и кэш

Контроллер отдаёт байты с MIME из `target_type` (по умолчанию `image/png`). Результат кэшируется через `storage()` под URI запроса. TTL при записи кэша не передаётся, поэтому срок хранения задаёт адаптер.

Если меняются фильтры или глобальные настройки, очистите соответствующий кэш приложения, чтобы старые данные не выдавались по тому же URI.

## Ограничения изображений

До чтения сохранённого файла плагин проверяет число кадров и общий пиксельный лимит. ImageMagick также получает лимиты памяти, map, диска, времени и потоков. Каждый результат `resize`, `crop` и `cover` проверяется до операции. Настройте значения под приложение и системную политику ImageMagick; не повышайте их без оценки памяти и времени.

Для полного перечня параметров см. [конфигурацию](/projects/media/configuration), а для модели угроз загрузки — [безопасность](/projects/media/security).
