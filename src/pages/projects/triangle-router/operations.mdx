# Интеграция и эксплуатация

## Самостоятельный режим и Engine

В standalone-режиме приложение строит `simpleRouteDispatcher()` или `cachedRouteDispatcher()` и само передаёт ему нормализованные HTTP method и path. Функции возвращают dispatcher, чьи результаты приложение обрабатывает самостоятельно.

Engine bootstrap — отдельный путь: `Triangle\Router\Bootstrap` при наличии объекта сервера собирает маршруты из `config/route.php` и активных конфигураций плагинов. Файл маршрутов использует статический фасад, например:

```php
<?php

use Triangle\Router;

Router::get('/health', static fn () => response('ok'));
```

Не смешивайте standalone настройку data generator/dispatcher с Engine bootstrap, который сам собирает маршрутные конфиги и создаёт Engine dispatcher.

## Доверие и контроль доступа

Маршрут — это сопоставление, а не политика доступа. Проверяйте аутентификацию и авторизацию в middleware/обработчике приложения. Ограничивайте доступ к административным маршрутам независимо от того, насколько специфичен их путь.

Standalone caller должен отделить query string от path и выбрать корректную нормализацию/декодирование под используемую серверную среду. Не декодируйте URI несколько раз: неоднозначная нормализация может привести к несовпадению проверки доступа и маршрута.

## HTTP-семантика

Dispatcher сообщает `NOT_FOUND`, `METHOD_NOT_ALLOWED` или `FOUND`; приложение решает, какой response сформировать. Для 405 передайте клиенту `Allow`. Не предполагайте, что регистрация GET автоматически определяет требуемое поведение HEAD: зарегистрируйте нужный метод или обработайте его явно и проверьте тело/заголовки ответа.

Маршрутизатор не является заменой полного HTTP stack, service discovery, authorization system или response middleware приложения.
