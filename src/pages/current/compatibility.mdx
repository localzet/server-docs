# Совместимость и сравнение версий

Последний опубликованный пакет — `v7.0.4`; его исходники совпадают с текущим `main`. Устанавливайте стабильный выпуск через `composer require localzet/server:^7.0`. Для разработки доступны исходники `7.0.x-dev`.

### Изменения в выпусках 7.0.3 и 7.0.4

| Область | Server 7.0.2 | Server 7.0.4 |
|---|---|---|
| HTTP reverse proxy | Chunked framing мог накапливать неограниченную строку размера chunk и блок trailers | Ограничены размер chunk-строки и trailers; превышение отклоняется |
| TCP proxy | После connect ошибка backend могла запустить повтор к другому upstream | После connect клиентское соединение закрывается: часть потока уже могла попасть upstream |
| RESP2 | Не было лимитов вложенности и числа значений | Введены лимит глубины 64 и максимум 100 000 значений в frame |
| PID и runtime-файлы | Предсказуемые файлы в общей временной директории | PID читается только из принадлежащего процессу regular file; запись атомарна, status и startup lock используют приватный runtime-каталог |
| Несколько экземпляров | Разные явно заданные PID-файлы одного entry script могли делить lock | Для разных PID-файлов создаются отдельные runtime-каталоги и lock-файлы |

Выпуск `7.0.4` включает исправления `7.0.3` и дополнительно устраняет конфликт runtime-lock при нескольких экземплярах с разными `Server::$pidFile`.

Ниже сравниваются исходники текущего выпуска с тегом `v4.5.3`. Это сравнение исходного кода и манифестов, а не гарантия совместимости конкретного приложения.

| Область | `v4.5.3` | Текущий выпуск `v7.0.4` |
|---|---|---|
| PHP и обязательные зависимости | PHP `^8.1 \|\| ^8.2`; обязательны `ext-sockets`, `ext-pcntl`, `ext-posix`, `localzet/events` | PHP `>=8.1`; обязательны `ext-json` и `ext-ctype`; остальные интеграции объявлены как optional |
| Event loop | Собственный набор Linux drivers, включая `StreamSelect`, `ext-uv`, `ext-event` и `ext-ev` | `EventLoopFactory`: `event` → `ev` → Revolt → встроенный `Select`; Windows имеет отдельную реализацию, Swoole/Swow выбираются явно |
| Gateway и proxy | В исходниках тега нет компонентов `Gateway/HttpReverseProxy` и `Proxy/TcpProxy` | Добавлены HTTP/1.x reverse proxy, raw TCP proxy и общий `UpstreamPool` |
| Hot upgrade | В исходниках тега нет `Runtime/HotUpgradeBroker` | Добавлен Unix hot upgrade с `pcntl_exec()` и передачей listener descriptors на поддерживаемой среде |
| Публичный API | Сигнатуры и реализация отражают контракт тега 4.5.3 | API и runtime изменялись; используйте справочник текущей версии и проверяйте приложение тестами |

Ссылки на исходники: [`v4.5.3` composer.json](https://github.com/localzet/Server/blob/v4.5.3/composer.json), [`v7.0.4` composer.json](https://github.com/localzet/Server/blob/v7.0.4/composer.json), [сравнение тегов](https://github.com/localzet/Server/compare/v4.5.3...v7.0.4).

## Перед обновлением приложения

1. Зафиксируйте фактически установленную версию через `composer show localzet/server` и `composer.lock`.
2. Сверьте используемые классы, callbacks и конфигурацию с [API-справочником](/api-ref/server).
3. Проверьте обязательные и optional PHP extensions целевой среды.
4. Прогоните собственные unit, protocol и integration tests на текущей версии исходников.
5. Проверьте graceful shutdown, reload/upgrade, framing и работу сессий в staging до переключения production.

Нельзя переходить между этими версиями одной заменой Composer constraint: набор обязательных расширений, внутренний event loop, lifecycle и возможности proxy изменились. Контракт вашего приложения нужно проверять отдельно.

## PHP и платформы

- Минимальное требование текущего кода: PHP `>=8.1`; `ext-json` и `ext-ctype` обязательны.
- Основная CI-матрица выполняется на Linux с PHP 8.1–8.5.
- Windows использует отдельный backend и предназначен для однопроцессного режима; платформа не входит в указанную Linux CI-матрицу.
- На Unix supervisor и несколько workers требуют `pcntl` и `posix`. Hot upgrade также зависит от поддержки передачи listening descriptors; проверяйте runtime-команду `capabilities`.

## Optional интеграции и event loop

Redis и MongoDB нужны только для соответствующих session handlers. `ext-sockets` применяется отдельными возможностями, включая передачу listening descriptors при поддерживаемом hot upgrade.

На Unix автоматический выбор event loop имеет порядок `event` → `ev` → Revolt → Select. Явный выбор недоступного backend-а завершается ошибкой, а не скрытым fallback. Проверяйте окружение командой `php server.php capabilities --json`.
