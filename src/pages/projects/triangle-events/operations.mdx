# Конфигурация и эксплуатация

## Загрузка конфигурации

На старте Engine 9 bootstrap Events читает основной массив `event`, затем аналогичные конфигурации приложений и плагинов. Для каждой записи `имя события => список callbacks` bootstrap регистрирует listener. Некорректная структура или невызываемый callback приводит к `RuntimeException` при загрузке, поэтому проверяйте конфигурацию до запуска production.

```php
return [
    'report.generated' => [
        [App\Listeners\SendReport::class, 'handle'],
    ],
];
```

Плагин может иметь собственный `config/event.php`. Обработчики классов для конфигурации разрешаются через контейнер `support\Container`.

## Модель выполнения

`emit()` запускает callbacks синхронно в текущем процессе. Время выполнения listener входит в задержку операции, инициировавшей событие. Диспетчер хранит подписки в статических структурах процесса; он не реплицирует состояние между worker-процессами и не сохраняет сообщения при рестарте.

Для медленного I/O, повторных попыток, гарантированной доставки, расписания и межпроцессной координации используйте отдельный механизм фоновой обработки. Не помещайте в payload секреты, если они не нужны всем подписчикам.

## Ошибки и безопасность

Исключение listener включается в результаты `emit()` и, если доступен logging Engine, записывается в журнал. Это не делает бизнес-операцию успешной: вызывающий код должен анализировать возвращаемое значение и отдельно принимать решение о retry/ошибке.

Конфигурационные файлы и сами listeners исполняются как код приложения. Не загружайте их из недоверенных источников. Авторизация не входит в Events: передаваемые события и payload контролирует вызывающий код, а обработчики должны проверять собственные предпосылки и права.
