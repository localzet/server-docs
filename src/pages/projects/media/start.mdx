# Установка и первый запуск

Последний опубликованный тег Media — `v1.1.0`, он требует Engine `^8.1`. Эта инструкция описывает подготовку `2.0.0` под Engine 9. Не устанавливайте старый опубликованный пакет в приложение Engine 9.

## Требования

- PHP 8.1 или новее.
- Triangle Engine 9; разрешённая им версия Localzet Server 7 должна быть согласована в lock-файле приложения.
- PHP-расширения `curl`, `fileinfo` и `imagick`.
- Записываемый каталог для итоговых изображений.
- Адаптер приложения с методами базы данных и хранения, описанными в [настройках](/projects/media/configuration).

## Установка пакета

Для текущего опубликованного релиза `v1.1.0` на Engine 8:

```sh
composer require triangle/media:^1.1
```

После публикации `2.0.0` для Engine 9:

```sh
composer require triangle/media:^2.0
```

Проверьте фактически выбранные версии:

```sh
composer show triangle/media triangle/engine localzet/server
```

Плагин использует `view()` для HTML-маршрутов. Если они нужны, установите компонент `triangle/view` и добавьте шаблоны `index`, `form` и `image`. Если приложение отдаёт JSON или собственную страницу, замените эти контроллеры либо не открывайте соответствующие маршруты.

## Установите конфигурацию

Вызовите `Triangle\Media\Install::install()` в поддерживаемом lifecycle установки плагинов приложения. Он копирует отсутствующие файлы из `src/Config` в `config/plugin/triangle/media` и не перезаписывает уже существующие настройки.

Для первого запуска проверьте:

1. `image_path` указывает на доступный для записи каталог.
2. `image_uri` — публичный базовый URL с завершающим `/`.
3. `database.images` и `database.projects` совпадают с именами таблиц/коллекций вашего адаптера.
4. `project_registration` оставлен `false`, если приложению не нужна открытая регистрация.
5. Адаптеры `db()` и `storage()` соответствуют контрактам плагина.

## Подключите маршруты

Engine регистрирует контроллеры через Composer autoload. По умолчанию префикс плагинов — `/app`; проверьте `app.plugin_uri` в конфигурации приложения и настройте reverse proxy так, чтобы upload endpoint был доступен только через требуемую политику приложения.

Встроенные HTML-маршруты требуют шаблоны представлений. Сам пакет не создаёт шаблоны, не настраивает веб-сервер и не публикует каталог хранения автоматически.

## Проверьте запуск

В каталоге пакета выполните локальные проверки:

```sh
composer validate --strict --no-check-publish --no-interaction
composer run check --no-interaction
composer audit --locked --no-interaction
```

В тестовой среде должны быть доступны расширения из `composer.json`, включая `imagick`. Локальная проверка пакета не проверяет реальные маршруты, права каталога, базу данных, кэш и шаблоны вашего приложения.
