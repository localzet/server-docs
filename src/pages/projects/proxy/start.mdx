# Proxy: начало работы

Localzet Proxy `1.0.2` — HTTP forward proxy для Server 7 с обязательной Basic-аутентификацией и allowlist IPv4/IPv6. Установите стабильную версию:

```sh
composer config repositories.localzet-proxy vcs https://github.com/localzet/Proxy
composer require localzet/proxy:^1.0
```

Создайте `proxy.php`:

```php
<?php

use localzet\Proxy;

require __DIR__ . '/vendor/autoload.php';

$proxy = new Proxy('tcp://127.0.0.1:8080');
$proxy->name = 'restricted-forward-proxy';
$proxy->count = 1;
$proxy->username = getenv('PROXY_USERNAME') ?: '';
$proxy->password = getenv('PROXY_PASSWORD') ?: '';
$proxy->allowedHosts = ['203.0.113.10'];
$proxy->allowedPorts = [80, 443];

if ($proxy->username === '' || $proxy->password === '') {
    throw new RuntimeException('Set proxy credentials before starting.');
}

Proxy::runAll();
```

Запустите локально:

```sh
php proxy.php start
```

Проверьте, что неразрешённые host и port отклоняются. Разрешённый CONNECT можно проверить клиентом `curl`:

```sh
curl --proxy http://127.0.0.1:8080 --proxy-user "$PROXY_USERNAME" http://203.0.113.10/health
```

When no password is included in `--proxy-user`, curl prompts for it instead of putting the password in shell history or process arguments. Replace the documentation-only IP with a reachable, approved literal address; the proxy rejects hostnames.

Basic credentials передаются открытым текстом внутри HTTP. Размещайте listener в доверенной зашифрованной сети или за TLS terminator. Прокси удаляет `Proxy-Authorization` и `Proxy-Connection` из HTTP-запроса перед отправкой целевому серверу. В `allowedHosts` задавайте буквальные IPv4/IPv6 адреса, не доменные имена. Сохраните исходящий firewall/ACL и учитывайте, что прокси обрабатывает один запрос на клиентское соединение. Остальные ограничения перечислены в [API и эксплуатации](/projects/proxy/reference).
