# Proxy: API и эксплуатация

Требуются PHP 8.1+ и Localzet Server `^7.0`. Класс `localzet\Proxy` наследуется от Server и принимает `new Proxy($socketName, $socketContext = [])`. Listener и число worker настраиваются через свойства Server.

## Политика исходящих подключений

```php
$proxy->allowedHosts = ['api.example.org'];
$proxy->allowedPorts = [443];
```

Пустой список `allowedHosts` запрещает все назначения. Сопоставление hostname точное, без учёта регистра; порт сравнивается по точному номеру. Реализуются HTTP absolute-form запросы и `CONNECT`. В исходящий поток передаётся полученный HTTP buffer, CONNECT после успешного соединения начинает двунаправленный TCP pipe.

Прокси не имеет встроенной клиентской аутентификации. Разрешённое DNS имя может резолвиться в loopback, private, link-local или иной запрещённый адрес; код не закрепляет и не фильтрует DNS ответы. Сетевой egress firewall обязателен, если доступ к чувствительным сетям должен быть закрыт. Не слушайте публичный интерфейс без внешних ACL и доверенного auth ingress.

## Границы реализации и проверки

Пакет не является reverse proxy, HTTP/2 proxy или production gateway с полной политикой маршрутизации. Протокол HTTP-запроса обрабатывается имеющимся callback; перед реальным трафиком проверьте framing и поведение больших/частичных запросов на целевом Server. Тесты: `composer test`, `composer test:integration`, `composer lint`. Интеграция проверяет loopback HTTP, CONNECT и отказ upstream, но не DNS rebinding, защиту private ranges, аутентификацию клиента или нагрузочную устойчивость.
