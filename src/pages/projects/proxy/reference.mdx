# Proxy: API и эксплуатация

Требуются PHP 8.1+ и Localzet Server `^7.0`. Класс `localzet\Proxy` наследуется от Server и принимает `new Proxy($socketName, $socketContext = [])`. Listener и число worker настраиваются через свойства Server.

## Политика исходящих подключений

```php
$proxy->username = getenv('PROXY_USERNAME') ?: '';
$proxy->password = getenv('PROXY_PASSWORD') ?: '';
$proxy->allowedHosts = ['203.0.113.10'];
$proxy->allowedPorts = [443];
```

Непустые `username` и `password` обязательны; credentials сверяются в формате HTTP Basic через constant-time comparison. Они передаются открытым текстом в HTTP заголовке, поэтому используйте TLS transport или доверенную сеть. Для обычного HTTP forwarding заголовки `Proxy-Authorization` и `Proxy-Connection` удаляются перед отправкой upstream; при `CONNECT` прокси устанавливает TCP tunnel после успешной проверки. Пустой список `allowedHosts` запрещает все назначения. Разрешайте буквальные IPv4/IPv6 адреса; IPv6 в запросах указывается в квадратных скобках, например `[2001:db8::1]`, а в allowlist — в обычной записи `2001:db8::1`. Hostname отклоняются. Порт сравнивается по точному номеру. Реализуются HTTP absolute-form запросы и `CONNECT`.

Basic-аутентификация не шифрует трафик; используйте TLS ingress и сетевой egress firewall. Не слушайте публичный интерфейс без внешних ACL.

## Границы реализации и проверки

Пакет не является reverse proxy, HTTP/2 proxy или production gateway с полной политикой маршрутизации. Он обрабатывает один запрос на клиентское соединение. Перед реальным трафиком проверьте framing и поведение больших/частичных запросов на целевом Server. Тесты: `composer test`, `composer test:integration`, `composer lint`; loopback integration покрывает Basic auth без передачи proxy-заголовков upstream, HTTP, CONNECT, allowlist, malformed request и upstream failure.
