# Совместимость и сравнение версий

Последний выпуск — `v7.2.3`. Устанавливайте его через `composer require localzet/server:^7.2`. Пакеты `^7.0` также допускают обновление в пределах Server 7; перед развёртыванием сверяйте выбранную версию через `composer show localzet/server`.

### Изменения в выпуске 7.2.3

| Область | Server 7.2.2 | Server 7.2.3 |
|---|---|---|
| HTTP gateway | Chunked-тело накапливалось в tracker | Переданные upstream байты удаляются; остаются только неполные framing-данные |
| HTTP parser | Прогресс chunked-разбора мог теряться между чтениями | Parser сохраняет прогресс и не пересканирует ранее разобранные данные |
| Multipart-формы | Не было общего предела числа частей | По умолчанию — 1 024 части; при превышении `post()` или `file()` выбрасывает `LengthException` до создания временных файлов |

Если приложение принимает формы с большим числом полей или файлов, проверьте это ограничение до обновления. Приложение должно преобразовать `LengthException` в нужный HTTP-ответ. Предел можно настроить для конкретного приложения; пример приведён в разделе [HTTP и загрузки](/current/http).

### Изменения в выпуске 7.2.2

| Область | Server 7.2.1 | Server 7.2.2 |
|---|---|---|
| TLS ALPN в HTTP и WebSocket | HTTP-кодеки не отклоняли согласованный протокол, отличный от `http/1.1` | Соединение закрывается, если ALPN выбрал другой протокол; данные `h2` не разбираются как HTTP/1.x |

Проверьте TLS-клиентов и прокси, которые задают список ALPN. Встроенные HTTP и WebSocket кодеки обслуживают только `http/1.1` и не реализуют HTTP/2.

### Изменения в выпуске 7.2.1

| Область | Server 7.2.0 | Server 7.2.1 |
|---|---|---|
| TLS `onConnect` | Callback мог вызываться до завершения TLS handshake | Callback вызывается после успешного handshake; для неуспешного handshake callback не запускается |
| Обычный TCP | Callback вызывается после подключения | Поведение не изменилось |

Проверка включает mTLS-сценарии с доверенным, отсутствующим и недоверенным клиентским сертификатом. Приложениям, которые полагались на вызов TLS `onConnect` до завершения handshake, следует проверить эту логику с новым порядком вызова.

### Изменения в выпуске 7.2.0

| Область | Server 7.1.0 | Server 7.2.0 |
|---|---|---|
| Взаимная проверка TLS | Настройка не была описана отдельным проверенным сценарием | Документация показывает настройку client CA; интеграционный тест проверяет доверенный, отсутствующий и недоверенный сертификат до вызова HTTP callback |
| Graceful shutdown во время callback | Отложенное закрытие соединения хранилось как динамическое поле connection | Состояние хранится в `WeakMap` сервера и применяется после завершения callback |

mTLS использует стандартные TLS stream-context параметры PHP. Проверка цепочки сертификатов не сопоставляет сертификат с пользователем приложения и не заменяет авторизацию.

### Изменения в выпуске 7.1.0

| Область | Server 7.0.4 | Server 7.1.0 |
|---|---|---|
| Lifecycle callbacks | Нет общих startup и worker-start hooks | Добавлены `Server::onBeforeRun()` и `Server::onWorkerStart()` |
| Остановка группы | Worker не мог запросить штатную остановку всей группы через публичный API | Добавлен `Server::requestShutdown()`; на Unix master завершает workers с graceful drain |
| Hot upgrade | Возможность зависела от возможностей runtime и передачи listener descriptors | Требуются PHP 8.4+ и `ext-sockets` с `SOCK_CLOEXEC`; при отсутствии флага сервер запускается без hot upgrade |

PHP 8.1–8.3 остаются поддерживаемыми для обычного запуска. Они не предоставляют нужный API создания socket pair с `SOCK_CLOEXEC`, поэтому hot upgrade там отключён.

### Предыдущие исправления в выпусках 7.0.3 и 7.0.4

| Область | Server 7.0.2 | Server 7.0.4 |
|---|---|---|
| HTTP reverse proxy | Chunked framing мог накапливать неограниченную строку размера chunk и блок trailers | Ограничены размер chunk-строки и trailers; превышение отклоняется |
| TCP proxy | После connect ошибка backend могла запустить повтор к другому upstream | После connect клиентское соединение закрывается: часть потока уже могла попасть upstream |
| RESP2 | Не было лимитов вложенности и числа значений | Введены лимит глубины 64 и максимум 100 000 значений в frame |
| PID и runtime-файлы | Предсказуемые файлы в общей временной директории | PID читается только из принадлежащего процессу regular file; запись атомарна, status и startup lock используют приватный runtime-каталог |
| Несколько экземпляров | Разные явно заданные PID-файлы одного entry script могли делить lock | Для разных PID-файлов создаются отдельные runtime-каталоги и lock-файлы |

Выпуск `7.0.4` включает исправления `7.0.3` и дополнительно устраняет конфликт runtime-lock при нескольких экземплярах с разными `Server::$pidFile`.

Ниже сравниваются исходники текущего выпуска с тегом `v4.5.3`. Это сравнение исходного кода и манифестов, а не гарантия совместимости конкретного приложения.

| Область | `v4.5.3` | Текущий выпуск `v7.2.3` |
|---|---|---|
| PHP и обязательные зависимости | PHP `^8.1 \|\| ^8.2`; обязательны `ext-sockets`, `ext-pcntl`, `ext-posix`, `localzet/events` | PHP `>=8.1`; обязательны `ext-json` и `ext-ctype`; остальные интеграции объявлены как optional |
| Event loop | Собственный набор Linux drivers, включая `StreamSelect`, `ext-uv`, `ext-event` и `ext-ev` | `EventLoopFactory`: `event` → `ev` → Revolt → встроенный `Select`; Windows имеет отдельную реализацию, Swoole/Swow выбираются явно |
| Gateway и proxy | В исходниках тега нет компонентов `Gateway/HttpReverseProxy` и `Proxy/TcpProxy` | Добавлены HTTP/1.x reverse proxy, raw TCP proxy и общий `UpstreamPool` |
| Hot upgrade | В исходниках тега нет `Runtime/HotUpgradeBroker` | Unix hot upgrade сохраняет listener descriptors; требуется PHP 8.4+ с нужной поддержкой socket flags |
| Публичный API | Сигнатуры и реализация отражают контракт тега 4.5.3 | API и runtime изменялись; используйте справочник текущей версии и проверяйте приложение тестами |

## Перед обновлением приложения

1. Зафиксируйте фактически установленную версию через `composer show localzet/server` и `composer.lock`.
2. Сверьте используемые классы, callbacks и конфигурацию с [API-справочником](/api-ref/server).
3. Проверьте обязательные и optional PHP extensions целевой среды.
4. Прогоните собственные unit, protocol и integration tests на текущей версии исходников.
5. Проверьте graceful shutdown, reload/upgrade, framing и работу сессий в staging до переключения production.

Нельзя переходить между этими версиями одной заменой Composer constraint: набор обязательных расширений, внутренний event loop, lifecycle и возможности proxy изменились. Контракт вашего приложения нужно проверять отдельно.

## PHP и платформы

- Минимальное требование текущего кода: PHP `>=8.1`; `ext-json` и `ext-ctype` обязательны.
- Основная CI-матрица выполняется на Linux с PHP 8.1–8.5.
- Windows использует отдельный backend и предназначен для однопроцессного режима; платформа не входит в указанную Linux CI-матрицу.
- На Unix supervisor и несколько workers требуют `pcntl` и `posix`. Hot upgrade требует PHP 8.4+, `ext-sockets` с `SOCK_CLOEXEC` и передачи listening descriptors. На PHP 8.1–8.3 сервер работает без hot upgrade; проверяйте runtime-команду `capabilities`.

## Optional интеграции и event loop

Redis и MongoDB нужны только для соответствующих session handlers. `ext-sockets` применяется отдельными возможностями, включая передачу listening descriptors при поддерживаемом hot upgrade.

На Unix автоматический выбор event loop имеет порядок `event` → `ev` → Revolt → Select. Явный выбор недоступного backend-а завершается ошибкой, а не скрытым fallback. Проверяйте окружение командой `php server.php capabilities --json`.
