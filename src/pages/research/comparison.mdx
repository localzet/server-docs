# Как выбирать серверный runtime

Сравнительная таблица «быстрее/медленнее» без одинакового приложения, конфигурации и нагрузки не помогает принять техническое решение. Здесь нет неподтверждённых цифр или рейтинга реализаций.

## Проверяйте требования проекта

| Вопрос | Что проверить у Localzet Server |
|---|---|
| Нужны ли долгоживущие TCP/UDP/WebSocket соединения? | Есть transport/protocol support; проверьте application framing и lifecycle |
| Нужен ли HTTP API? | Реализован HTTP/1.x, не HTTP/2/3 |
| Требуется ли многопроцессность? | На Unix нужны `pcntl` и `posix`; на Windows описан однопроцессный режим |
| Нужен ли shared state? | Настройте session handler или внешний storage; память workers не общая |
| Нужны ли встроенные auth, rate limits, service discovery? | Это обязанности приложения/edge; gateway не предоставляет эти системы |
| Какая версия пакета будет установлена? | Проверяйте фактический Composer version: stable release 4.x отделён от текущих исходников 7.x |
| Какова ожидаемая нагрузка? | Измерьте своё приложение на целевой инфраструктуре; у проекта нет универсальной capacity гарантии |

## Сравнивайте через одинаковый сценарий

Для каждого кандидата используйте один и тот же workload, data store, TLS termination, размер payload, concurrency, hardware и error budget. Сравнивайте и latency distribution, и корректность при shutdown, disconnect, partial framing и перегрузке.

Ветку 7.x сначала проверяйте в staging: она отличается от опубликованной compatibility линии. См. [совместимость](/current/compatibility) и [методологию benchmark-а](/research/benchmarks).
