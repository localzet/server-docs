# HTTP-запросы и ответы

## Путь запроса

Localzet Server принимает соединение и разбирает HTTP-сообщение. Engine HTTP устанавливает текущие объекты запроса и соединения в Engine Context, затем ищет обработчик по методу и пути. Проверки идут для ранее собранных callback-ов, небезопасного URI, статического файла, зарегистрированного маршрута, маршрута контроллера и fallback-а.

Router выполняет сопоставление маршрута. Middleware оборачивает callback; контроллеры и зависимости разрешаются Triangle Engine. Адаптер сам по себе не добавляет авторизацию: её настраивает приложение или его middleware.

## Результат обработчика

Обработчик может вернуть ответ Server или Engine. Для базового HTTP-ответа Server 7 адаптер сохраняет код, заголовки и тело. Обычное значение оборачивается в ответ Engine с кодом 200 и строковым представлением результата. Исключения передаются настроенному обработчику ошибок.

~~~php
use localzet\Server\Protocols\Http\Response;
use Triangle\Router;

Router::any('/health', static fn () => new Response(
    200,
    ['Content-Type' => 'application/json'],
    '{"status":"ok"}',
));
~~~

Тело и заголовки формирует приложение. Не возвращайте пользовательский ввод как HTML без контекстного кодирования.

## Keep-alive и файлы

Отправка учитывает версию HTTP и заголовок Connection запроса. Для HTTP/1.1 без явного закрытия соединение остаётся открытым; также учитывается ответ с Transfer-Encoding: chunked. Байтовую отправку, framing и backpressure выполняет Server.

Статические файлы возвращаются как файловый ответ. PHP-файл внутри public-пути исполняется только при явно включённой опции app.support_php_files; по умолчанию она выключена.
