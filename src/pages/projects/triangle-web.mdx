# Triangle Web

Triangle Web — приложение-шаблон с MVC-структурой на Triangle Engine и Triangle HTTP. Опубликованный выпуск — [`v8.0.1`](https://github.com/Triangle-org/Web/releases/tag/v8.0.1). Тип Composer — `project`; в опубликованном манифесте PHP `^8.2`, `ext-curl`, `ext-json`, Engine `^8.1`, Engine HTTP `^2.0`, Console `^1.3`, Database `^1.0`, Session `^1.0`, View `^2.0`, Events `^1.0`. Текущий checkout `dc1335b1` — четыре коммита после тега; manifest сохраняет эти constraints, а preview lock и CI относятся к текущему checkout.

```sh
composer create-project triangle/web:^8.0 my-web-app
cd my-web-app
composer show triangle/engine triangle/engine-http triangle/web
```

## Первые маршруты и контроллер

Точка входа `master` загружает Composer autoload, задаёт пути, загружает `.env`, вызывает Engine autoloader и запускает Console. Серверные параметры задаются в `config/server.php`; исходный шаблон слушает `http://127.0.0.1:8000`, число workers по умолчанию равно `cpu_count() * 4`.

В `config/route.php` маршрут регистрируется через Router:

```php
use Triangle\Request;
use Triangle\Response;
use Triangle\Router;

Router::any('/hello/{name}', function (Request $request, string $name): Response {
    return response("Привет, $name!");
});
```

В шаблоне `app/controller/Index.php` показаны методы, возвращающие `response(...)`, `responseJson(...)` и `view('index/view', [...])`. Views настраиваются в `config/view.php`; renderer выбирается через `VIEW_HANDLER` (`raw` по умолчанию, также перечислены blade/think/twig). Пример HTTP запуска — `php master start`; фактические CLI команды сверяйте с установленным Triangle Console.

## Конфигурация и эксплуатация

Шаблон включает `config/` для server, routes, middleware, database, session, view, logging, events и других интеграций. Каталог `public` предназначен для публичных файлов, `runtime` — для служебных файлов по конфигурации проекта. Изменяйте только нужные параметры и храните секреты в окружении, а не в tracked config.

В исходном `config/app.php` включён `debug=true`, а CORS заголовки заданы широко: origin `*`, credentials `true`, методы/headers `*`. Перед production явно задайте debug=false и согласуйте origin, credentials, методы и заголовки с доверенными клиентами. Не полагайтесь на эти значения как на безопасную политику. Ограничьте bind address и сетевой доступ; default loopback слушатель не делает сервис публичным.

## Совместимость и проверки

Release `v8.0.1` ограничивает Engine до `^8.1` и включает компоненты соответствующих major-линий; это не установка на Engine 9. Проверьте совместимость проекта перед совместным обновлением Triangle компонентов. `composer.json` не объявляет lint/test scripts, поэтому для этого checkout нет заявленной пакетной команды автотестов. HTTP smoke/integration checks должны выполняться в приложении с установленными версиями зависимостей. Текущий README содержит только badges; описание на этой странице сверено с entry point, конфигурацией, контроллером и маршрутом.
